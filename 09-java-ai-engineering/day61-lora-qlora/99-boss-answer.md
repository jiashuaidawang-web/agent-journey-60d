# Day 61 Boss 答案

## 1. LoRA 的核心思想是什么？低秩分解的数学原理是什么？

**LoRA 的核心思想**：

LoRA（Low-Rank Adaptation）的核心思想是**不修改原始模型参数，而是注入可训练的低秩矩阵来捕获任务相关的变化**。

全量微调需要更新模型的所有参数量（如 7B 模型需要更新 70 亿参数），而 LoRA 发现大模型的权重变化集中在低维子空间，因此可以用低秩矩阵来近似这些变化。

**低秩分解的数学原理**：

1. **原始权重矩阵**：$W \in \mathbb{R}^{d \times k}$，参数量为 $d \times k$

2. **LoRA 引入两个低秩矩阵**：
   - $A \in \mathbb{R}^{r \times k}$（下投影矩阵，用高斯分布初始化）
   - $B \in \mathbb{R}^{d \times r}$（上投影矩阵，用零初始化）
   - 其中 $r \ll \min(d, k)$（秩远小于原始维度）

3. **前向传播**：
   - 原始：$h = Wx$
   - LoRA：$h = Wx + BAx = (W + BA)x$
   - $W$ 冻结，$A$ 和 $B$ 可训练

4. **参数量计算**：
   - 原始：$d \times k$
   - LoRA：$r \times (d + k)$
   - 压缩率：$1 - \frac{r(d+k)}{dk}$

5. **缩放因子**：
   - 实际更新：$\Delta W = \frac{\alpha}{r} BA$
   - $\alpha$ 是缩放因子，控制 LoRA 更新的强度
   - 当 $\alpha = r$ 时，缩放为 1

**实际案例**（以 LLaMA-7B 为例）：
- 注意力层 $W_q$ 维度：4096 × 4096 = 16,777,216 参数
- LoRA（r=16）：16 × 4096 + 4096 × 16 = 131,072 参数
- 压缩率：99.2%

## 2. 微调的关键参数有哪些？它们是如何影响训练效果的？

**关键参数详解**：

| 参数 | 说明 | 推荐值 | 影响 |
|------|------|--------|------|
| **learning rate** | 学习率 | 1e-4 ~ 5e-4 | 太大不收敛，太小收敛慢 |
| **batch size** | 批次大小 | 8 ~ 32 | 太大显存不足，太小梯度不稳定 |
| **epochs** | 训练轮数 | 3 ~ 10 | 太少欠拟合，太多过拟合 |
| **LoRA rank (r)** | 低秩维度 | 8 ~ 64 | 太小表达能力不足，太大显存增加 |
| **LoRA alpha** | 缩放因子 | 通常 = rank | 控制更新强度 |
| **LoRA dropout** | Dropout 率 | 0.05 ~ 0.1 | 防止过拟合 |
| **target_modules** | 应用 LoRA 的层 | q_proj, v_proj | 影响哪些层被微调 |
| **max_length** | 最大序列长度 | 512 ~ 2048 | 太长显存消耗大 |

**参数关系**：

1. **rank 和 alpha 的关系**：
   - 实际缩放因子 = alpha / rank
   - 通常设 alpha = rank，缩放因子为 1
   - alpha > rank 时，LoRA 更新更强

2. **learning rate 和 epochs 的关系**：
   - 高学习率 + 少 epochs = 快速收敛但可能不稳定
   - 低学习率 + 多 epochs = 稳定收敛但耗时

3. **batch size 和 learning rate 的关系**：
   - 大 batch size 可以用高 learning rate
   - 小 batch size 建议用低 learning rate

**调参建议**：
- 初次微调：r=16, alpha=32, lr=2e-4, epochs=3
- 效果不佳：增大 r 或增加数据
- 过拟合：增加 dropout 或减少 epochs
- 欠拟合：增大 lr 或增加 epochs

## 3. QLoRA 是如何进一步降低显存的？它的核心技术是什么？

**QLoRA 的核心目标**：

在 LoRA 的基础上，进一步降低基座模型的显存占用，使 7B 模型可以在单张 GPU（如 RTX 3090 24GB）上微调。

**三大核心技术**：

**1. 4-bit NormalFloat（NF4）量化**
- 传统的均匀量化假设权重均匀分布，但神经网络权重服从正态分布
- NF4 是非均匀量化，将权重映射到 16 个（4-bit）最优分位点
- 每个权重从 FP16（16 bit）降到 4 bit，显存降低 75%
- 性能损失 < 1%

**2. Double Quantization（双重量化）**
- 量化常数（quantization constants）也占用显存
- 对量化常数再进行一次量化（如 8-bit 量化）
- 进一步节省约 0.5 bit/参数 的显存

**3. Paged Optimizers（分页优化器）**
- 梯度检查点（Gradient Checkpointing）会导致显存尖峰
- 使用 NVIDIA 统一内存，在显存不足时自动分页到 CPU
- 防止 OOM（Out of Memory）

**显存对比**（7B 模型）：

| 方法 | 基座显存 | 优化器显存 | 总显存 |
|------|----------|------------|--------|
| FP16 全量微调 | 14GB | 80GB | ~100GB |
| LoRA（FP16） | 14GB | 4GB | ~20GB |
| QLoRA（4-bit） | 3.5GB | 4GB | ~8GB |

**QLoRA 的优势**：
- 7B 模型可以在单张 24GB GPU 上微调
- 65B 模型可以在单张 48GB GPU 上微调
- 性能损失 < 1%（相比 FP16）

## 4. 微调数据应该如何获取和清洗？

**数据获取策略**：

**1. 开源数据集**
- **Alpaca**：52K 条指令数据，英文
- **ShareGPT**：真实对话数据，多轮
- **OpenAssistant**：多轮对话，高质量
- **Chinese-LLaMA-Alpaca**：中文指令数据
- **bellkeat/alpaca-gpt4-data**：GPT-4 生成的高质量数据

**2. 自定义数据**
- 从业务日志提取
- 人工标注
- LLM 辅助生成（Self-Instruct）
- 数据增强（回译、改写）

**数据格式**：
```json
{
    "instruction": "翻译成英文",
    "input": "你好世界",
    "output": "Hello World"
}
```

**数据清洗流程**：

1. **去重**：删除重复样本（基于文本相似度）
2. **去噪**：删除低质量、乱码、广告
3. **长度过滤**：删除过长（>2048 token）或过短（<10 token）样本
4. **格式统一**：统一数据格式（instruction/input/output）
5. **质量评分**：使用规则或模型评分，过滤低质量

**清洗示例**：
- 原始数据：52,002 条
- 去重后：51,800 条
- 去噪后：51,500 条
- 长度过滤后：50,000 条
- 最终可用：50,000 条

**数据质量的重要性**：
- 高质量数据 > 大量低质量数据
- 1000 条高质量数据可能比 10000 条低质量数据效果好
- 数据质量直接影响微调效果

## 5. 如何评估微调模型的效果？

**评估指标**：

**1. 自动指标**
- **BLEU**：机器翻译质量（n-gram 精确率）
- **ROUGE**：文本摘要质量（n-gram 召回率）
- **Perplexity**：语言模型困惑度（越低越好）
- **Accuracy**：分类任务准确率

**2. 人工评估**
- **流畅度**：生成文本是否通顺（1-5 分）
- **相关性**：是否回答了问题（1-5 分）
- **准确性**：信息是否准确（1-5 分）
- **一致性**：是否与上下文一致（1-5 分）

**3. 任务指标**
- **准确率**：分类/问答任务的正确率
- **召回率**：信息检索的召回率
- **F1**：准确率和召回率的调和平均

**评估方法**：

**1. 单轮评估**
- 给定输入，评估输出质量
- 适用于指令遵循任务

**2. 多轮评估**
- 模拟多轮对话，评估一致性
- 适用于对话任务

**3. 对比评估**
- 微调模型 vs 基座模型
- 微调模型 vs GPT-4

**评估流程**：
1. 准备测试集（100-1000 条）
2. 运行模型生成
3. 计算自动指标
4. 人工评估（抽样 100 条）
5. 对比分析
6. 输出评估报告

**优化建议**：
- 自动指标和人工评估结合
- 关注业务指标（如用户满意度）
- 持续监控模型效果
- 定期更新测试集
