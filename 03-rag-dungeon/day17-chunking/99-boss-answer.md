# Day 17 Boss 答案

## 1. 为什么文档要分块？

**原因**：
1. **Context Window 有限**：即使是 128K 模型也放不下整本书
2. **嵌入模型限制**：大多数嵌入模型有 token 上限（如 512 tokens）
3. **检索精度**：小块更容易精确匹配用户查询
4. **成本**：小块减少 LLM 的 Token 消耗

**类比**：
- 不分块：把整本书塞进数据库，查询时返回整本书
- 分块：把书拆成章节，查询时只返回相关章节

## 2. Chunk Size 如何影响检索效果？

| Chunk Size | 优势 | 劣势 |
|------------|------|------|
| 小（128-256） | 精确匹配 | 上下文不足 |
| 中（256-512） | 平衡 | 通用 |
| 大（512-1024） | 上下文丰富 | 噪声多 |

**选择建议**：
- 问答场景：小-中（精确匹配）
- 总结场景：中-大（需要上下文）
- 通用：512 tokens + 50 overlap

## 3. Overlap 的作用是什么？

**Overlap（重叠）**：相邻 Chunk 之间共享一部分内容。

**作用**：
1. **防止信息切断**：避免关键信息被切在两个 Chunk 的边界
2. **提高召回**：同一个信息可能在多个 Chunk 中
3. **上下文连续**：LLM 看到的内容更连贯

**代价**：
- 存储增加
- 可能有重复结果（需要去重）

**推荐值**：Chunk Size 的 10-20%（如 512 的 overlap 是 50-100）
