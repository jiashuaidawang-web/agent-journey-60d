# Day 56 Boss 答案

## 1. OpenAI 和 DeepSeek 有什么区别？各适合什么场景？

**OpenAI**：
- 全球最强通用模型，GPT-4o / GPT-5 在推理、代码、多模态方面领先
- 价格较高，GPT-4o 输入 $2.5/1M tokens，输出 $10/1M tokens
- 英文能力最强，中文能力中等
- 工具调用（Function Calling）最稳定
- 适合：需要最强能力、英文为主、预算充足的场景

**DeepSeek**：
- 国产模型，DeepSeek V3 性价比极高
- 价格极低，输入 ￥1/1M tokens，输出 ￥2/1M tokens
- 中文能力强，代码能力突出
- 工具调用支持良好
- 适合：中文场景、成本敏感、代码生成

**对比**：

| 维度 | OpenAI GPT-4o | DeepSeek V3 |
|------|---------------|-------------|
| 价格 | 高（$2.5/1M） | 低（￥1/1M） |
| 中文能力 | 中 | 强 |
| 工具调用 | 强 | 强 |
| 推理能力 | 最强 | 强 |
| 多模态 | 强 | 弱 |

**选择建议**：预算充足选 OpenAI，成本敏感选 DeepSeek，实际项目中可以混合使用（简单任务 DeepSeek，复杂任务 OpenAI）。

## 2. Ollama 本地部署的优势和劣势是什么？什么场景下应该用 Ollama？

**Ollama 优势**：
1. **隐私优先**：数据不出本地，适合金融、医疗、政务等敏感场景
2. **零成本**：无需 API 费用，只需硬件投入
3. **离线可用**：不依赖网络，适合内网环境
4. **完全控制**：模型、参数、数据完全自主
5. **快速启动**：一条命令即可运行模型

**Ollama 劣势**：
1. **性能受限**：取决于本地硬件，高端 GPU 才能跑大模型
2. **模型能力有限**：本地模型通常弱于云端大模型
3. **维护成本**：需要自己管理模型更新、硬件维护
4. **扩展性差**：无法像云端那样弹性扩展

**适用场景**：
- 金融 / 医疗 / 政务：数据敏感，合规要求高
- 内网环境：无法访问外网
- 边缘计算：IoT、嵌入式设备
- 开发测试：快速验证 AI 能力
- 隐私优先应用：个人助手、本地知识库

**代码示例**：
```yaml
spring:
  ai:
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: llama3.2
```

## 3. 如何设计一个多模型动态切换系统？需要考虑哪些因素？

**设计方案**：

1. **模型注册表**：维护可用模型列表和配置
2. **路由策略**：根据任务类型、成本、延迟选择模型
3. **降级机制**：主模型故障时自动切换备用
4. **可观测性**：记录每次调用的模型、耗时、成本

**核心代码**：
```java
@Service
public class ModelRouterService {

    private final Map<String, ChatClient> modelMap;

    public ModelRouterService(
        @Qualifier("openAiChatClient") ChatClient openAiClient,
        @Qualifier("ollamaChatClient") ChatClient ollamaClient
    ) {
        this.modelMap = Map.of(
            "openai", openAiClient,
            "ollama", ollamaClient
        );
    }

    public String chat(String model, String input) {
        ChatClient client = modelMap.getOrDefault(model, modelMap.get("openai"));
        return client.prompt().user(input).call().content();
    }
}
```

**考虑因素**：
- **成本**：不同模型价格差异大，按任务复杂度路由
- **延迟**：本地模型延迟低，云端模型延迟高
- **能力**：复杂任务用强模型，简单任务用便宜模型
- **合规**：敏感数据用本地模型
- **可用性**：主模型故障时自动降级

## 4. 国内合规要求下，应该选择哪些模型平台？

**国内合规要求**：
- 数据本地化：用户数据不能出境
- 内容审核：输出内容需符合国内法规
- 备案要求：AI 服务需通过相关部门备案
- 实名制：用户需实名使用

**推荐平台**：

| 平台 | 合规性 | 特点 |
|------|--------|------|
| 阿里百炼 | ✅ 完全合规 | 通义千问，国内领先 |
| 百度文心 | ✅ 完全合规 | 文心一言，搜索增强 |
| 智谱 | ✅ 完全合规 | GLM-4，开源友好 |
| DeepSeek | ⚠️ 部分合规 | 需确认数据出境情况 |
| OpenAI | ❌ 不合规 | 数据出境 |

**选择建议**：
- 金融 / 政务 / 医疗：必须选择国内合规平台（阿里百炼 / 百度 / 智谱）
- 一般企业：可选择国内平台或确认 DeepSeek 合规性
- 个人 / 测试：无特殊要求

## 5. 模型选型的核心决策因素是什么？请按优先级排序。

**优先级排序**（从高到低）：

1. **合规性**：是否满足国内法规要求（一票否决）
2. **业务需求**：任务复杂度、中文能力、工具调用、多模态
3. **成本**：API 价格、硬件投入、维护成本
4. **延迟**：响应时间要求、用户体验
5. **可用性**：服务稳定性、SLA 保障
6. **生态支持**：文档、社区、SDK 完善程度
7. **可扩展性**：未来需求变化时的灵活性

**决策树**：
```
合规？ → 否 → 排除
      → 是 → 继续
        │
业务需求匹配？ → 否 → 排除
              → 是 → 继续
                │
成本可接受？ → 否 → 排除
            → 是 → 继续
              │
延迟满足？ → 否 → 排除
          → 是 → 选择
```

**实际建议**：没有"最好"的模型，只有"最适合"的模型。根据业务场景做权衡，实际项目中通常采用多模型混合策略。
