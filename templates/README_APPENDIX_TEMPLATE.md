## 🤖 Codex / Claude Code 任务

### 今天 AI 可以帮你
- 解释 <相关技术> 的核心概念
- 解释 <相关框架/库> 的用法
- 帮你调试代码报错
- 对比不同实现的优劣

### 今天 AI 不能帮你
- 替你理解概念（你必须自己理解）
- 替你写完整代码（你必须自己敲）
- 替你回答 Boss（你必须自己想）

### 正确用法
> "<针对该 day 主题的合理提问示例，比如：我有 Java 经验，Python 的 XX 机制不太熟，请用 Java 的 YY 类比解释一下，然后给我一个最小示例。>"

### 错误用法
> "<直接要答案的示例，比如：帮我写一个完整的 XX 系统。>"

## 📝 GitHub 提交规范

### 提交结构
```
<module>/
└── <day-folder>/
    ├── README.md           # 学习总结
    ├── LEARNING_FLOW.md    # 学习流程
    ├── 00_<file>.py         # <说明>
    ├── 01_<file>.py         # <说明>
    ├── ...
    ├── 99-boss-answer.md   # Boss 答案
    └── requirements.txt
```

### README.md 必须包含
```markdown

（记录踩过的坑）

## 代码运行截图
（贴终端输出）
```

```bash
git add <module>/<day-folder>/
```

# 使用说明

1. **替换占位符**：`<module>`、`<day-folder>`、`<相关技术>`、`<相关框架/库>`、`<概念1>` 等需替换为该 day 的实际内容。
2. **动态生成**：".py 文件清单"和"Commit 规范"中的文件树，必须基于该 day 重命名后的实际文件。
3. **正确用法示例**：必须与该 day 主题相关，不能套模板。
4. **位置**：追加在 README.md 末尾（🔓 解锁条件之后）。
