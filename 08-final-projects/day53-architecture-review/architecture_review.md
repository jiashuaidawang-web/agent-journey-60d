# 架构答辩准备

## 项目一：Enterprise Agent Platform

### 1. 项目背景

**问题**：企业需要一个生产级的 Agent 平台，支持多租户、成本控制、高可用。

**解决方案**：Java + Python 混合架构，发挥各自优势。

### 2. 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                        前端 / API Gateway                        │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│                   Java Control Plane (Spring Boot)               │
│  ┌──────────────┬──────────────┬──────────────┬──────────────┐  │
│  │  租户管理     │  权限鉴权     │  任务调度     │  成本核算     │  │
│  └──────────────┴──────────────┴──────────────┴──────────────┘  │
└───────────────────────────────┬─────────────────────────────────┘
                                │ HTTP/gRPC
┌───────────────────────────────▼─────────────────────────────────┐
│                    Python AI Service (LangGraph)                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                Agent Runtime (LangGraph)                  │   │
│  └──────────────────────────────────────────────────────────┘   │
│  ┌──────────┬──────────┬──────────┬──────────────────────────┐  │
│  │  RAG     │  MCP     │  Skill   │  Evaluation              │  │
│  └──────────┴──────────┬──────────┴──────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### 3. 技术选型

| 层级 | 技术 | 原因 |
|------|------|------|
| 控制平面 | Java (Spring Boot) | 企业级能力、稳定性、生态 |
| AI 服务 | Python (LangGraph) | 快速迭代、AI 生态 |
| RAG | Dense + BM25 + Reranker | 混合检索，兼顾语义和关键词 |
| 协议 | MCP 3.0 | 工具标准化 |
| 通信 | HTTP/gRPC | 跨语言通信 |

### 4. 难点和解决方案

| 难点 | 解决方案 |
|------|----------|
| 多租户隔离 | 数据、配额、性能、安全四个维度 |
| 成本控制 | 模型路由、Token 统计、配额限制 |
| 生产稳定性 | Retry、Circuit Breaker、Timeout |
| 可观测性 | Trace、Metrics、Logging、Alert |

### 5. 面试亮点

- Java + Python 混合架构，发挥各自优势
- 多租户隔离设计
- 成本优化策略
- 全链路追踪

## 项目二：AI Investment Research Platform

### 1. 项目背景

**问题**：投研需要多维度分析（行业、公司、市场、风险），单一 Agent 难以胜任。

**解决方案**：Supervisor + 多 Agent 协作架构。

### 2. 架构设计

```
                    ┌──────────────┐
                    │  Supervisor  │
                    │   Agent      │
                    └──────┬───────┘
                           │
        ┌────────┬─────────┼─────────┬────────┐
        ▼        ▼         ▼        ▼        ▼
   ┌────────┐┌────────┐┌────────┐┌────────┐┌────────┐
   │Industry││Company ││Financial││Market  ││  Risk  │
   │Research││Research││Analysis││Sentiment││Analysis│
   │ Agent  ││ Agent  ││ Agent  ││ Agent  ││ Agent  │
   └────────┴────────┴────────┴────────┴────────┘
```

### 3. 技术选型

| 层级 | 技术 | 原因 |
|------|------|------|
| 协调层 | Supervisor Agent | 任务分解、Agent 调度 |
| 执行层 | 专业 Agent | 每个 Agent 专注一个领域 |
| 能力层 | Skills | 业务能力封装 |
| 工具层 | MCP | 标准化工具接口 |
| 数据层 | RAG + GraphRAG | 混合检索，支持多跳推理 |

### 4. 难点和解决方案

| 难点 | 解决方案 |
|------|----------|
| Agent 协作 | Supervisor 统一协调 |
| 能力复用 | Skills 层封装，多 Agent 复用 |
| 工具标准化 | MCP 协议统一接口 |
| 知识获取 | RAG + GraphRAG 混合检索 |

### 5. 面试亮点

- Supervisor 多 Agent 架构
- Skills 层能力封装
- MCP 工具标准化
- GraphRAG 多跳推理

## 面试常见问题

### 架构类

1. **为什么用 Java + Python 混合架构？**
   - Java 擅长企业级能力（租户、权限、调度、成本）
   - Python 擅长 AI 编排（LangGraph、RAG）
   - 发挥各自优势

2. **如何保证高可用？**
   - 无状态设计，支持水平扩展
   - 失败降级（模型降级、Agent 降级）
   - 熔断机制

3. **如何扩展？**
   - 新增 Agent：注册到 Supervisor
   - 新增 Skill：添加到 Skill Registry
   - 新增 Tool：通过 MCP 注册

### 技术类

1. **LangChain vs LangGraph？**
   - LangChain 适合线性流程
   - LangGraph 适合复杂 Agent（多步、分支、循环）

2. **MCP vs Function Calling？**
   - Function Calling 是 LLM 能力
   - MCP 是工具标准化协议

3. **RAG vs Fine-tuning？**
   - RAG：知识更新快，成本低
   - Fine-tuning：深度适配，成本高

### 场景类

1. **如果 Agent 死循环怎么办？**
   - Max Iterations 限制
   - 重复检测
   - Token 预算

2. **如何控制成本？**
   - 模型路由（根据复杂度选择模型）
   - Token 统计
   - 配额限制

3. **如何保证安全？**
   - Prompt Injection 防护
   - 权限控制
   - 审计日志
