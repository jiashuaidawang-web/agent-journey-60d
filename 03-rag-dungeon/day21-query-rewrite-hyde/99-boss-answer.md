# Day 21 Boss 答案

## 1. 为什么需要查询重写？

**用户查询的问题**：
1. **模糊**："白酒龙头" → 不够具体
2. **简短**："电池龙头股" → 缺少上下文
3. **表达差异**：用户查询和文档表达方式不同

**查询重写的作用**：
- 补充缺失信息
- 转换为更适合检索的形式
- 提升召回率

## 2. HyDE 的原理是什么？

**HyDE（Hypothetical Document Embeddings）**：

流程：
```
查询 → LLM 生成假设文档 → 嵌入假设文档 → 向量搜索
```

**核心思想**：
- 查询是"问题"，文档是"答案"
- 用 LLM 生成一个"假设的答案"
- 用这个假设答案的向量去搜索真实文档
- 文档-文档相似度 > 查询-文档相似度

**为什么有效？**
- 假设文档的向量空间更接近真实文档
- 比直接用查询向量搜索更准确

## 3. HyDE 比普通检索好在哪？

**优势**：
1. **召回率更高**：文档-文档匹配比查询-文档匹配更准确
2. **处理模糊查询**：LLM 可以补充缺失信息
3. **语义理解更深**：生成的假设文档包含更多上下文

**劣势**：
1. **成本更高**：需要额外 LLM 调用
2. **延迟增加**：生成假设文档需要时间
3. **依赖 LLM 质量**：假设文档质量影响检索效果

**适用场景**：
- 查询模糊、简短
- 对召回率要求高
- 能接受额外成本
