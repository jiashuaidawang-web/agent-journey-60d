# Day 43 Boss 答案

## 1. 为什么需要 GraphRAG？

**传统 RAG 的局限**：
- 基于块检索，无法捕捉实体间关系
- 难以回答需要多跳推理的问题
- 缺乏全局视角

**GraphRAG 的优势**：
- 实体关系建模
- 多跳推理能力
- 全局视角（Community Summary）

## 2. GraphRAG 的流程？

```
1. 文档输入
   ↓
2. 实体抽取（Entity Extraction）
   - 从文本中抽取实体（人物、公司、地点等）
   ↓
3. 关系抽取（Relationship Extraction）
   - 抽取实体间的关系
   ↓
4. 知识图谱构建
   - 实体作为节点，关系作为边
   ↓
5. 社区检测（Community Detection）
   - 聚类相关实体
   ↓
6. 社区摘要（Community Summary）
   - 为每个社区生成摘要
   ↓
7. 图检索
   - 根据查询检索相关实体和关系
   ↓
8. LLM 生成
   - 基于检索结果生成回答
```

## 3. GraphRAG 和 RAG 的区别？

| 维度 | RAG | GraphRAG |
|------|-----|----------|
| 检索方式 | 向量相似度 | 图遍历 |
| 推理能力 | 单跳 | 多跳 |
| 全局视角 | 弱 | 强 |
| 适用 | 简单问答 | 复杂推理 |
| 实体关系 | 不建模 | 建模 |
