# Day 20 Boss 答案

## 1. 为什么需要重排序？

**召回阶段的局限**：
- Bi-Encoder 速度快但精度有限
- 无法捕捉查询和文档的细粒度交互
- Top 20 中可能有不相关文档

**重排序的作用**：
- 对召回结果进行精确排序
- Cross-Encoder 能捕捉细粒度语义
- 提升最终 Top 5 的精度

**类比**：
- 召回：海选（快速筛选候选人）
- 精排：面试（深入评估候选人）

## 2. Cross-Encoder 和 Bi-Encoder 的区别？

| 维度 | Bi-Encoder | Cross-Encoder |
|------|------------|---------------|
| 编码方式 | 查询和文档分别编码 | 查询+文档拼接编码 |
| 向量 | 可以预计算文档向量 | 无法预计算 |
| 速度 | 快（可用 ANN） | 慢（需要逐一计算） |
| 精度 | 中等 | 高 |
| 阶段 | 召回 | 精排 |
| 模型 | BGE-M3 | bge-reranker |

**原理差异**：
- Bi-Encoder：`sim(encode(query), encode(doc))`
- Cross-Encoder：`score(encode(query + doc))`

## 3. 两阶段检索的优势？

**优势**：
1. **效率**：召回阶段快速筛选（ANN），精排阶段精确计算
2. **精度**：两阶段结合，兼顾召回率和精确率
3. **可扩展**：召回阶段支持大规模文档（百万级）
4. **平衡**：效率和精度的最佳平衡

**流程**：
```
查询 → 召回（Top 20）→ 精排（Top 5）→ LLM
        快（10ms）       慢（100ms）      生成
```
