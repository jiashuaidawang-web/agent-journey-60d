# Day 6 Boss 答案

## 1. ReAct 和 Router 的适用场景有什么不同？

**ReAct 适用场景**：
- 单任务、需要多步推理
- 任务可以分解为多个步骤
- 每步依赖上一步的结果
- 例如："帮我分析一家公司" → 搜索 → 获取财务数据 → 分析 → 输出报告

**Router 适用场景**：
- 多领域、多任务
- 每个任务类型有专门的处理逻辑
- 任务之间相对独立
- 例如：一个客服系统，需要处理天气查询、股票查询、计算等不同请求

**核心区别**：

| 维度 | ReAct | Router |
|------|-------|--------|
| 任务数 | 单任务多步 | 多任务分发 |
| 核心 | 推理链 | 意图识别 |
| 复杂度 | 步骤间有依赖 | 子任务独立 |
| 扩展性 | 增加工具 | 增加子 Agent |

**选择建议**：
- 如果你的系统要处理**多种不同类型的请求** → Router
- 如果你的系统要处理**复杂的多步任务** → ReAct
- 实际系统通常是**混合**：Router 分发到子 Agent，子 Agent 内部用 ReAct

## 2. 什么场景下用 Plan-and-Execute？

**Plan-and-Execute 适用场景**：
- 任务复杂，步骤多（>5步）
- 步骤之间有明确的依赖关系
- 需要全局规划，不能走一步看一步
- 例如：写一份行业研究报告、规划一次旅行、开发一个功能

**为什么 ReAct 不够？**
- ReAct 是"走一步看一步"，没有全局视角
- 可能做了很多无用功，才发现方向错了
- 复杂任务容易陷入局部最优

**Plan-and-Execute 的优势**：
- 先规划，后执行，有全局视角
- 计划可以动态调整（执行中发现问题可以修改计划）
- 适合并行执行（多个步骤可以同时进行）

**实际案例**：
```
任务："帮我写一份新能源行业研究报告"

Plan:
1. 搜索新能源行业概况
2. 搜索主要公司（宁德时代、比亚迪等）
3. 分析政策环境
4. 分析技术趋势
5. 撰写报告

Execute:
  并行执行 1, 2, 3（互不依赖）
  → 完成后执行 4（依赖 1, 2, 3）
  → 最后执行 5（依赖 4）
```

## 3. Router 模式如果路由错误怎么办？

**路由错误的原因**：
- 意图识别错误（LLM 理解错了）
- 用户输入模糊（"帮我看看这个"）
- 多个意图相似（"分析一下天气" → 天气分析？还是分析天气对股票的影响？）

**处理策略**：

1. **置信度阈值**：
   - 意图识别时输出置信度
   - 低于阈值（如 0.6）→ 不路由，反问用户

2. **澄清反问**：
   - "你是想查天气还是查股票？"
   - 让用户明确意图

3. **Fallback Agent**：
   - 设置一个默认 Agent 处理未知意图
   - 或者直接告诉用户"我不太确定你的意思"

4. **二次确认**：
   - "我理解你想查询天气，对吗？"
   - 用户确认后再执行

5. **记录错误，持续优化**：
   - 记录路由错误的 case
   - 分析原因，优化意图识别 Prompt
   - 添加更多训练示例

**代码示例**：
```python
intent = self.detect_intent(user_input)
confidence = self.get_intent_confidence(user_input)

if confidence < 0.6:
    return "我不太确定你的意思。你是想查天气、股票，还是做计算？"

sub_agent = self.route(intent)
if sub_agent is None:
    return "暂时不支持这个功能"
```
