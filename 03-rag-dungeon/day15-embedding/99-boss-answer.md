# Day 15 Boss 答案

## 1. Embedding 的本质是什么？

**Embedding（嵌入）** 是将文本转换为高维向量的过程。

**本质**：
- 文本 → 固定维度的浮点数向量（如 1024 维）
- 语义相似的文本，向量在空间中距离近
- 语义不同的文本，向量在空间中距离远

**为什么这样设计？**
- 计算机不能直接理解文本，只能处理数字
- 向量空间可以表示语义关系
- 通过向量运算可以衡量语义相似度

**例子**：
```
"苹果" → [0.12, 0.34, -0.56, ..., 0.78]
"香蕉" → [0.15, 0.31, -0.52, ..., 0.80]  ← 与"苹果"相似
"汽车" → [-0.45, 0.22, 0.67, ..., -0.12] ← 与"苹果"不相似
```

## 2. 为什么 RAG 不能只用关键词匹配？

**关键词匹配（BM25）的问题**：

1. **无法理解语义**：
   - 查询："水果" → 无法匹配"苹果"（字面不同）
   - 查询："iPhone" → 无法匹配"苹果手机"（同义词）

2. **无法处理改写**：
   - "如何学习Python" vs "Python学习方法" → 关键词匹配不上

3. **无法处理多语言**：
   - "苹果" vs "apple" → 关键词匹配不上

**Embedding 检索的优势**：
- 语义相似 → 向量相似 → 能匹配
- 同义词、改写、多语言都能处理
- 召回率大幅提升

**实际案例**：
```
查询："白酒龙头股"
关键词匹配：只能匹配包含"白酒龙头股"的文档
Embedding 匹配：能匹配"贵州茅台是白酒龙头企业"（语义相似）
```

**结论**：现代 RAG 系统通常使用 **混合检索**（Embedding + BM25）兼顾语义和关键词。

## 3. Cosine Similarity 怎么计算？

**Cosine Similarity（余弦相似度）**：

公式：
```
cos(A, B) = dot(A, B) / (||A|| * ||B||)
```

其中：
- `dot(A, B)` = A·B = Σ(Ai * Bi)（点积）
- `||A||` = sqrt(Σ(Ai²))（向量模长）

**几何意义**：
- 计算两个向量夹角的余弦值
- 夹角越小 → 余弦值越大 → 越相似
- 夹角越大 → 余弦值越小 → 越不相似

**值域**：
- `1.0`：完全相同方向（最相似）
- `0`：垂直（无关）
- `-1.0`：完全相反方向（最不相似）

**代码**：
```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
```

**为什么用 Cosine 而不是 Euclidean Distance？**
- Cosine 只关注方向，不关注长度
- 文本嵌入向量的长度不携带语义信息
- Cosine 更适合衡量语义相似度
