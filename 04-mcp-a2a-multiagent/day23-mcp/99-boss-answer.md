# Day 23 Boss 答案

## 1. MCP 和 Function Calling 有什么区别？

| 维度 | Function Calling | MCP |
|------|------------------|-----|
| 定义 | LLM 输出工具调用的能力 | 工具标准化协议 |
| 范围 | LLM → 工具 | LLM ↔ 工具 ↔ 数据源 |
| 标准化 | 各家不同（OpenAI、Anthropic） | 统一开放协议 |
| 复用性 | 低（每个应用单独实现） | 高（一次开发，多处复用） |
| 生态 | 封闭 | 开放生态 |
| 适用场景 | 简单工具调用 | 复杂工具集成 |

**核心区别**：
- Function Calling 是 LLM 的"能力"（能输出工具调用）
- MCP 是"协议"（标准化工具如何被定义、发现、调用）

**类比**：
- Function Calling = 手机能打电话
- MCP = 移动通信协议（5G）

## 2. MCP 的核心概念有哪些？

| 概念 | 说明 | 作用 |
|------|------|------|
| Tools | 工具 | LLM 可以调用的函数 |
| Resources | 资源 | 数据源（文件、数据库等） |
| Prompts | 提示词模板 | 预定义的提示词 |
| Server | 服务端 | 提供工具/资源 |
| Client | 客户端 | 调用工具/资源 |

**三者关系**：
```
MCP Server
├── Tools（工具）
│   ├── get_weather
│   ├── search_stock
│   └── calculate
├── Resources（资源）
│   ├── file://data/report.pdf
│   └── db://users
└── Prompts（提示词）
    ├── summarize
    └── translate
```

## 3. MCP 的架构是什么？

**MCP 架构**：

```
┌─────────────────────────────────────────┐
│           LLM Application (Client)       │
│  ┌───────────────────────────────────┐  │
│  │         MCP Client                │  │
│  │  - 发现工具（tools/list）         │  │
│  │  - 调用工具（tools/call）         │  │
│  │  - 读取资源（resources/read）     │  │
│  └───────────────────────────────────┘  │
└───────────────────┬─────────────────────┘
                    │ MCP Protocol
                    │ (JSON-RPC 2.0)
┌───────────────────▼─────────────────────┐
│              MCP Server                  │
│  ┌───────────────────────────────────┐  │
│  │  Tools  │ Resources │ Prompts     │  │
│  └───────────────────────────────────┘  │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│          External Systems                │
│  ┌─────────┬─────────┬──────────────┐  │
│  │ Database│   API   │    Files     │  │
│  └─────────┴─────────┴──────────────┘  │
└─────────────────────────────────────────┘
```

**通信方式**：
- **stdio**：标准输入输出（本地）
- **Streamable HTTP**：HTTP 流式（远程）
