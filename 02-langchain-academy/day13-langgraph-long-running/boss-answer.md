# Day 13 Boss 答案

## 1. Subgraph 的作用是什么？

**Subgraph（子图）的作用**：

1. **模块化**：把复杂任务拆分为多个子图
2. **复用**：同一个子图可以在多个父图中使用
3. **抽象**：父图不需要关心子图内部实现
4. **可维护**：每个子图独立开发、测试、维护

**类比**：
- Subgraph ≈ Java 的 Service / Component
- Parent Graph ≈ 组合多个 Service 的 Controller

## 2. 为什么要用 Subgraph 而不是一个大 Graph？

**大 Graph 的问题**：
- 节点过多，难以理解和维护
- 所有节点耦合在一起
- 无法复用某个子流程
- 测试困难

**Subgraph 的优势**：

| 维度 | 大 Graph | Subgraph |
|------|----------|----------|
| 可读性 | 差 | 好 |
| 可维护性 | 差 | 好 |
| 复用性 | 无 | 高 |
| 测试 | 困难 | 容易 |
| 协作 | 困难 | 容易 |

## 3. 长时间运行 Agent 如何保证可靠性？

**可靠性保障**：

1. **Checkpoint**：每个节点后保存状态，支持断点续跑
2. **interrupt**：关键节点暂停，等待人工确认
3. **Subgraph 隔离**：子图失败不影响其他子图
4. **错误处理**：每个节点可以捕获异常，决定下一步
5. **超时控制**：设置最大执行时间
6. **Token 预算**：设置 Token 上限，防止成本失控
