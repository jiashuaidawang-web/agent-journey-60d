# 从 文本 -> 答案 的全流程
用户输出文本: 你是什么大模型
|
1.分词器编码
token分词器 --. 讲文本分词,切序列化 101标识开始 中间的会把 "你是什么大模型切分且向量化以数字表示" 102标识结束 例如[101,123,1341,14,,124,124,114,333,55,102]
| 
2.嵌入层：Token序列→向量序列
向量ebeding 讲token序列转为向量序列,比如GPT-4是 12288 维度的向量,每个Token对应的向量都是一个包含12288个浮点数的数组
例如上面的: 转换后为: 8组 * 包含12288浮点数的数组
你是什么大模型对应的10个Token，就会转换成10个长度为12288的向量，组成一个10×12288的二维矩阵输入到模型里
|
3.解码器逐层处理:理解语义
向量序列会依次经过每一层解码器（比如GPT-4有96层），每层会做两件事：
自注意力机制：计算每个Token和其他Token的关联程度，比如让「你」和「什么」「大模型」建立语义联系
前馈神经网络：对每个Token的向量做非线性变换，提取更深层的语义特征
Transformer的核心工作流程
输入的10个token,回依次从第一层往下递进走
每一次把理解过的语义再以10个token的形式传递到下一次
没过一层,语义不同,但总token数不变
每层输出的向量序列长度不变（还是10个Token），维度也不变（还是12288维），只是每个Token对应的向量数值会被不断调整，语义信息越来越丰富。

1. 自注意力机制（Self-Attention）
让每个Token能看到序列里其他所有Token的信息，建立语义关联：
比如处理「你是什么大模型」的时候，经过注意力机制，「你」对应的向量里会融入「什么」「大模型」的语义信息，不再是孤立的单个字的向量。

具体计算过程：

每个Token的向量会生成三个新向量：查询向量（Q）、键向量（K）、值向量（V）
用每个Token的Q去和所有Token的K做点积，得到注意力权重（表示和其他Token的关联程度）
再用权重对所有Token的V做加权求和，得到新的向量
2. 前馈神经网络（Feed Forward Network）
对每个Token的新向量做非线性变换，提取更复杂的特征：

每个Token的向量独立经过两层全连接层，维度会先升维再降维（比如先升到49152维，再降回12288维）
这一步可以让模型学习到更复杂的语义模式，比如语法结构、上下文逻辑

举个通俗的例子
假设我们要理解「我想吃苹果，但是它太贵了」这句话：

第1~10层：主要学习基础语法，知道「它」是代词，和前面的名词有关联
第11~40层：学习语义关联，知道「它」指代的是「苹果」，不是其他东西
第41~96层：学习深层逻辑，理解整个句子表达的是「因为苹果价格高，所以不想买」的意思
每一层都在上一层的基础上，提取更高级的特征，层数越深，理解越抽象、越准确。

关键点
每一层都会处理整个向量序列，不会改变序列的长度和维度，只会更新向量的数值
层数越深，向量里包含的上下文信息越丰富，语义理解越准确
所有计算都是并行的，不需要等上一个Token处理完再处理下一个，所以生成速度很快

这10个token是一起从第一层走到第96层,不需要一个token走一遍
所以这就可能是高并发的一个点
可以打包10个请求,比如一个请求的token数是10,那就是一起让100个token从第一层到最后一层,这样并发直接提升了10倍

|
4. 预测下一个Token：生成输出
生成阶段的核心规则
第0轮输入（原始输入）：[101, 2345, 678, 9012, 3456, 102]
生成第1个新Token：1234（我）

第1轮输入：[101, 2345, 678, 9012, 3456, 102, 1234]
生成第2个新Token：5678（是）

第2轮输入：[101, 2345, 678, 9012, 3456, 102, 1234, 5678]
生成第3个新Token：9012（G）

...以此类推，直到生成102（结束标记），停止生成

为什么这么设计？
因为Transformer的注意力机制需要完整的上下文才能准确预测下一个Token：

比如生成「是」的时候，需要知道前面有「我」，才能组成完整的「我是」
生成「G」的时候，需要知道前面是「我是」，才能继续生成「GPT助手」
如果每次只输入新生成的Token，没有前面的上下文，模型根本不知道该怎么继续生成
这样设计的代价
随着生成的Token越来越多，每一轮输入的序列会越来越长，计算量也会越来越大：

第1轮：输入7个Token，计算量是7×12288×96层
第10轮：输入16个Token，计算量是16×12288×96层
第100轮：输入106个Token，计算量是106×12288×96层
这也是长回复生成速度越慢，且占用内存越多的原因，所以大模型的上下文长度都会有限制，避免序列太长导致计算资源耗尽。

优化方法
实际部署中不会真的每轮都重新计算所有Token，而是会用KV缓存（KV Cache）：

把之前所有Token的K、V向量缓存起来，下一轮只需要计算新Token的Q，和缓存的K、V做注意力计算
这样每轮的计算量只需要1×12288×96层，不需要重复计算之前的Token，速度可以提升几倍甚至几十倍
